# 보안 강화 요구사항

## 📋 개요

Notion RAG 시스템의 보안 취약점을 식별하고 개선하여 프로덕션 환경에서 안전하게 운영할 수 있도록 합니다.

## 🚨 발견된 보안 취약점

### 1. CORS 설정 (심각도: 높음)
**현재 상태:**
```python
allow_origins=["*"]  # 모든 도메인 허용
allow_credentials=True
allow_methods=["*"]
allow_headers=["*"]
```

**문제점:**
- 모든 도메인에서 API 접근 가능 (CSRF 공격 위험)
- 인증 정보 포함 요청을 모든 도메인에서 허용
- XSS 공격을 통한 데이터 탈취 가능

**요구사항:**
- 허용된 도메인만 명시적으로 설정
- 환경 변수로 CORS 설정 관리
- 프로덕션 환경에서는 특정 도메인만 허용

### 2. API 인증/인가 부재 (심각도: 높음)
**현재 상태:**
- 모든 엔드포인트가 인증 없이 접근 가능
- `/sync`, `/append`, `/create-page` 등 민감한 작업 무제한 허용

**문제점:**
- 누구나 Notion 페이지 수정/생성 가능
- 누구나 동기화 트리거 가능 (리소스 남용)
- 세션 하이재킹 가능

**요구사항:**
- API 키 기반 인증 구현
- JWT 토큰 기반 인증 옵션 제공
- 쓰기 작업에 대한 권한 검증
- Rate Limiting 구현

### 3. 입력 검증 부족 (심각도: 중간)
**현재 상태:**
- `page_id`, `content`, `title` 등 입력값 검증 없음
- SQL Injection은 없지만 NoSQL Injection 가능성

**문제점:**
- 악의적인 입력으로 시스템 오작동 유발 가능
- 매우 긴 입력으로 DoS 공격 가능
- 특수 문자로 인한 오류 발생 가능

**요구사항:**
- 입력값 길이 제한
- 특수 문자 필터링
- Pydantic 모델에 검증 규칙 추가
- 페이지 ID 형식 검증

### 4. 민감 정보 노출 (심각도: 중간)
**현재 상태:**
```python
# /health 엔드포인트에서 노출
"ollama": config["OLLAMA_BASE_URL"],  # 내부 서버 URL 노출
"total_chunks": stats["total_chunks"],  # 시스템 정보 노출
```

**문제점:**
- 내부 인프라 정보 노출
- 에러 메시지에 스택 트레이스 포함 가능
- 시스템 구조 파악 용이

**요구사항:**
- 프로덕션 환경에서 민감 정보 마스킹
- 에러 메시지 일반화
- 디버그 모드와 프로덕션 모드 분리

### 5. 세션 관리 취약점 (심각도: 중간)
**현재 상태:**
```python
chat_sessions = {}  # 메모리에 저장, 영구 저장 없음
```

**문제점:**
- 서버 재시작 시 모든 세션 손실
- 세션 만료 없음 (메모리 누수)
- 세션 ID 예측 가능성 (UUID v4 사용 중이지만 검증 없음)

**요구사항:**
- 세션 만료 시간 설정
- 세션 저장소 개선 (Redis 등)
- 세션 ID 검증 강화
- 동시 세션 수 제한

### 6. Rate Limiting 부재 (심각도: 중간)
**현재 상태:**
- 모든 엔드포인트에 요청 제한 없음

**문제점:**
- DoS 공격에 취약
- 리소스 남용 가능
- Ollama 서버 과부하 가능

**요구사항:**
- IP 기반 Rate Limiting
- 엔드포인트별 제한 설정
- 동기화 작업 동시 실행 방지

### 7. 로깅 및 모니터링 부족 (심각도: 낮음)
**현재 상태:**
- 기본 print 문만 사용
- 보안 이벤트 로깅 없음

**문제점:**
- 공격 탐지 어려움
- 감사 추적 불가능
- 문제 발생 시 원인 파악 어려움

**요구사항:**
- 구조화된 로깅 (JSON 형식)
- 보안 이벤트 로깅 (인증 실패, 비정상 요청 등)
- 로그 레벨 설정 (DEBUG, INFO, WARNING, ERROR)
- 민감 정보 로그 제외

### 8. Dockerfile 보안 (심각도: 낮음)
**현재 상태:**
```dockerfile
FROM python:3.11-slim
WORKDIR /app
# root 사용자로 실행
```

**문제점:**
- root 권한으로 실행
- 불필요한 파일 포함 가능성

**요구사항:**
- 비특권 사용자로 실행
- 멀티 스테이지 빌드
- 최소 권한 원칙 적용

## 🎯 수용 기준

### 인증/인가
- [ ] API 키 기반 인증 구현
- [ ] 환경 변수로 API 키 관리
- [ ] 쓰기 작업에 인증 필수
- [ ] 인증 실패 시 401 응답

### CORS
- [ ] 허용 도메인 환경 변수로 설정
- [ ] 기본값은 localhost만 허용
- [ ] 프로덕션 환경 가이드 문서화

### 입력 검증
- [ ] 모든 입력값 길이 제한
- [ ] 페이지 ID 형식 검증
- [ ] 특수 문자 필터링
- [ ] 검증 실패 시 400 응답

### Rate Limiting
- [ ] IP 기반 제한 (분당 60회)
- [ ] 동기화 작업 동시 실행 방지
- [ ] 제한 초과 시 429 응답

### 로깅
- [ ] 구조화된 로깅 구현
- [ ] 보안 이벤트 로깅
- [ ] 민감 정보 마스킹
- [ ] 로그 레벨 환경 변수로 설정

## 📝 비기능 요구사항

### 성능
- 인증 오버헤드 < 10ms
- Rate Limiting 오버헤드 < 5ms

### 호환성
- 기존 API 엔드포인트 유지
- 인증 옵션으로 제공 (강제 아님)
- 환경 변수로 보안 기능 활성화/비활성화

### 문서화
- 보안 설정 가이드 작성
- API 키 생성 방법 문서화
- CORS 설정 예시 제공
